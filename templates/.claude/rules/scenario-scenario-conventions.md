# シナリオ設計規約

ゲームシナリオの設計・執筆における規約とチェックリスト。

---

## 構造原則

- シナリオは「文章」ではなく「ゲーム状態を変化させる仕様」として扱う
- フラグ・状態を先に設計し、テキストは後から詰める
- 分岐構造は企画段階で確定する（後工程での変更はコスト指数的増大）

## 物語構造の選定基準

| 構造     | 選定条件                         | コスト               | 自由度 |
| -------- | -------------------------------- | -------------------- | ------ |
| 線形     | 筆力勝負、アクション補助         | 低                   | 低     |
| 分岐     | マルチエンディングが体験の核     | 高                   | 高     |
| 折り返し | 一貫性と選択感の両立             | 中                   | 中     |
| 創発     | オープンワールド・サンドボックス | システム設計が支配的 | 最高   |

## ビジュアルノベル固有の規則

- **最初の100クリック以内に事件（Inciting Incident）を起こす**
- 日常パートは「退屈」ではなく「感情的投資」として設計する
- 結末から先に書き、伏線を逆算的に配置する
- ビジュアルで表現済みの要素をテキストで重複描写しない
- ADV/NVL形式の選択はジャンル・演出意図に基づいて決定する

## キャラクター設計の規則

- 全キャラクターに**欲求→葛藤→成長弧**の三軸を定義する
- 口調設定表を作成し、全ライターが参照する
  - 一人称、語尾、敬語基準、感情別変化、禁止表現を明記
- キャラクターの知識状態を場面ごとに追跡する

## フラグ管理の規則

- 全フラグをスプレッドシートで一元管理する
- フラグ間の依存関係グラフを作成・維持する
- 選択肢は3種（展開変更型/情報整理型/雰囲気醸成型）に分類する
- 永続変数（周回データ）は明示的に設計・文書化する

## 品質チェックリスト

### 致命的（リリース前に必ず確認）

- [ ] フラグ矛盾がゼロであること
- [ ] デッドエンド（意図しない進行不能）がゼロであること
- [ ] 到達不能ノードがゼロであること
- [ ] 全エンディングに到達可能な経路が存在すること

### 重要（品質に直結）

- [ ] 全伏線が回収済みであること（Payoff率100%）
- [ ] キャラクターの口調が設定と一致すること
- [ ] キャラクターの知識状態に矛盾がないこと
- [ ] ルート間のテキスト量差が1.5倍以内であること

### 推奨

- [ ] 箱書きの全シーンに存在意義が明記されていること
- [ ] 用語集が最新の状態で維持されていること
- [ ] 演出指示（立ち絵・BGM・SE）が全シーンに記載されていること

## 禁止事項

- **論理矛盾の放置**：フラグ矛盾、因果関係の破綻を認知しながら修正しない
- **プレイヤー情報の漏洩**：プレイヤーがまだ知らないはずの情報をキャラクターが語る
- **偽りの選択肢の濫用**：結果が同一の選択肢を頻繁に提示し、プレイヤーの信頼を損なう
- **存在意義のないシーン**：物語的機能を持たないシーンを残す
- **口調設定の無視**：キャラクターシートの口調設定に従わない台詞を書く
