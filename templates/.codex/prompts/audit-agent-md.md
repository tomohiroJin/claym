
# Agent.md 監査スキル

既存の Agent 設定ファイル（CLAUDE.md / AGENTS.md / GEMINI.md）を監査し、コンテキストエンジニアリングのベストプラクティスに照らして改善提案を行います。


## 1. 対象ファイルの収集

```
1. プロジェクトルートの CLAUDE.md / AGENTS.md / GEMINI.md を読む
2. .claude/CLAUDE.md があれば併せて読む
3. .claude/rules/*.md を全て読む
4. .codex/AGENTS.md があれば読む
5. .gemini/GEMINI.md があれば読む
6. サブディレクトリの Agent.md も Glob で探索
```


## 2. 監査チェックリスト

各ファイルに対して以下の基準で評価する。

### 2.1 サイズと構造（重要）

| チェック項目 | 基準 | 理由 |
|------------|------|------|
| 行数 | **200行以内を目安** | 毎セッション読み込まれるため、長いほど個々の指示が埋もれる。行数だけで削除を判断せず、2.2 の内容基準と併せて評価する |
| 1行目 | プロジェクト名 + 技術スタックが凝縮 | ファイルの対象範囲が一目で分かる |
| セクション構造 | 見出し + 箇条書きで明確に構造化 | パース効率の向上 |

### 2.2 コンテンツ品質（重要）

| チェック項目 | 基準 | 理由 |
|------------|------|------|
| 自明な情報の排除 | 「TypeScript プロジェクトです」等が**ない** | エージェントがコードを読めば分かる情報はトークンの浪費 |
| 暗黙知の有無 | リンターでカバーできないルールが**ある** | /init では生成できない最大の価値 |
| コマンドの正確性 | ビルド・テスト・リントが**バッククォート内** | エージェントが直接実行可能 |
| 禁止事項 | Never do リストが**具体的** | 「注意してください」ではなく「絶対にしないこと」 |
| 地雷マップ | 技術的負債・特殊実装の記載 | システム破壊の防止 |

### 2.3 セキュリティ（致命的）

| チェック項目 | 基準 |
|------------|------|
| 機密情報の混入 | API キー、パスワード、トークンが**含まれていない** |
| .gitignore 整合性 | .local.md や settings.local.json が除外されている |
| 権限の三層構造 | Always do / Ask first / Never do が定義されている |

### 2.4 クロスツール整合性

| チェック項目 | 基準 |
|------------|------|
| 内容の一貫性 | 3つのファイル間でルールが矛盾していない |
| symlink 運用 | AGENTS.md を正本として統一管理されているか |
| ツール固有設定 | .gemini/settings.json, .codex/config.toml が適切か |
| フォールバック | Codex の project_doc_fallback_filenames が設定されているか |

### 2.5 アンチパターン検出

以下のパターンを検出し、警告する:

- **ペルソナの汎用化**: 「あなたは親切なアシスタントです」→ 効果なし。具体的な役割定義に変更
- **自明な情報の羅列**: /init で自動生成された内容がそのまま → 20%以上のトークンインフレ
- **巨大な単一ファイル**: 300行超 → モジュール分割が必要
- **曖昧な指示**: 「適切に対応してください」→ 具体的な手順に置換
- **リンターで代替可能なルール**: ESLint/Prettier で強制できるルールは Agent.md に書かない
- **更新されていない情報**: package.json と矛盾するバージョン情報
