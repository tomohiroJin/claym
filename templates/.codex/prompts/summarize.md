# 要約・文書分析

文書の特性と目的に応じた最適な要約戦略を選択し、高品質な要約を生成します。

---

## 1. 要約戦略の選択

### ハイブリッドアプローチ（推奨デフォルト）

1. **抽出型（Extractive）**: 原文から重要な文・数値・事実をそのまま抽出する
2. **抽象型（Abstractive）**: 抽出した要素を一貫した叙述に統合する

この2段階で、正確性と読みやすさを両立する。

### 長文書の戦略選択

| 戦略 | 適用場面 | 特徴 |
|------|---------|------|
| **Map-Reduce** | 独立した章・セクションがある文書 | 各チャンクを並列要約→統合。速度重視 |
| **反復洗練（Iterative Refinement）** | 文脈の一貫性が重要な文書 | 前セクションの要約を起点に逐次改善 |
| **階層的要約（RAPTOR）** | 大規模文書・複数文書の統合 | 再帰的にクラスタリング・要約しツリー構造を構築 |

### 選択基準

```
文書サイズ < 10,000 トークン → ハイブリッドアプローチで直接要約
文書サイズ 10,000-50,000 トークン → 反復洗練
文書サイズ > 50,000 トークン → Map-Reduce または RAPTOR
複数文書の統合 → RAPTOR
章が独立している → Map-Reduce
文脈の連続性が重要 → 反復洗練
```

## 2. プロンプトエンジニアリング技法

### XML タグによる構造化

Claude は XML タグで訓練されているため、入力の構造化に活用する。

```xml
<document>
[要約対象の文書をここに配置]
</document>

<instructions>
上記の文書を以下の形式で要約してください:
1. エグゼクティブサマリー（3文以内）
2. 主要ポイント（5項目以内）
3. 詳細な分析
</instructions>
```

### コンテキスト・ファースト順序

20,000 トークン以上の長文書はプロンプトの**先頭**に配置する。
クエリ先行配置と比較して、応答品質が最大 30% 向上する。

```
構成順序:
1. 長文書（先頭に配置）
2. 指示・制約条件
3. 出力形式の指定
```

### 引用優先戦略（Quote-First）

文書の関連箇所をまず引用させてからタスクを実行させることで、ハルシネーションを劇的に減少させる。

```
手順:
1. 「まず、[テーマ]に関連する箇所を原文から引用してください」
2. 「引用した内容に基づいて、要約を作成してください」
```

### Chain-of-Thought 分解

要約プロセスを段階的に明示する。

```
ステップ1: 文書の主要トピックを特定する
ステップ2: 各トピックの要点を抽出する
ステップ3: トピック間の関係性を分析する
ステップ4: 統合的な要約を生成する
```

### 制約の明示化

曖昧な指示を避け、具体的な制約を指定する。

```
悪い例: 「簡潔にまとめてください」
良い例: 「5つの箇条書き、各25語以内で要約してください」

悪い例: 「重要なポイントを抜き出してください」
良い例: 「ビジネス上の意思決定に影響する事実を、
        根拠データとともに3つ抽出してください」
```

## 3. 要約の実行手順

### ステップ 1: 文書の構造把握

```
1. 文書の種類を特定する（論文、報告書、記事、議事録等）
2. 全体構成（章立て・セクション）を確認する
3. 文書の目的と対象読者を把握する
4. 文書のサイズに応じた要約戦略を選択する
```

### ステップ 2: 抽出フェーズ

```
1. 各セクションの中心的主張・結論を特定する
2. 重要な数値・データ・事実を抽出する
3. キーワード・専門用語を記録する
4. 図表のキャプション・要旨を確認する
```

### ステップ 3: 統合フェーズ

```
1. 抽出した要素を論理的に整理する
2. セクション間の関係性（因果・対比・補完）を分析する
3. 重要度に応じた階層構造を構築する
4. 一貫した叙述に統合する
```

### ステップ 4: 品質検証

```
1. 原文の主要な主張が漏れなく反映されているか
2. 事実の歪曲・誤解がないか
3. 要約だけで文書の要旨が理解できるか
4. 指定された形式・分量の制約を満たしているか
```

## 4. ノートテイキング手法との統合

### Zettelkasten 法（知識の蓄積）

要約結果を永続的な知識として蓄積する場合に使用する。

```
原則:
- 原子性: 1ノート = 1アイデア
- 接続性: ノート間リンクでネットワーク化
- 自律性: 各ノートが自己完結
- 自分の言葉: 原文をコピーせず、自分の理解で記述

ノートの種類:
1. フリーティングノート（一時的な思いつき）
2. 文献ノート（出典付きコメント）
3. 永続ノート（自分の言葉で精緻化）
4. ハブノート（関連クラスターの入口）
```

### Progressive Summarization（段階的圧縮）

情報の重要度に応じて段階的に圧縮する。

```
Layer 0: 原文
Layer 1: キャプチャ（保存する価値のある部分を選択）
Layer 2: 太字強調（Layer 1 の中で特に重要な箇所）
Layer 3: ハイライト（Layer 2 の中で核心的な箇所）
Layer 4: 自分の言葉による要約

重要: 全ノートに全層を適用しない。
ノートの価値はべき分布に従い、繰り返し参照するノートのみ深い層まで処理する。
```

## 5. 出力フォーマット

### 階層的要約テンプレート

```markdown
# [文書タイトル] の要約

## エグゼクティブサマリー
[文書全体の要旨を 3-5 文で。最も重要な結論を最初に述べる]

## 主要ポイント
1. [ポイント1]: [1文の説明]
2. [ポイント2]: [1文の説明]
3. [ポイント3]: [1文の説明]

## 章別サマリー

### [章1タイトル]
- 要旨: [2-3文]
- 重要データ: [数値・事実]
- 著者の主張: [結論・推奨]

### [章2タイトル]
- 要旨: [2-3文]
- 重要データ: [数値・事実]
- 著者の主張: [結論・推奨]

## 詳細分析（必要に応じて）
[テーマ横断的な分析、パターンの特定、批判的評価]

## 原文からの重要引用
> [特に重要な原文の引用]（p.XX）

## メタ情報
- 文書種別: [論文/報告書/記事等]
- 著者: [著者名]
- 発行日: [日付]
- 要約作成日: [日付]
- 要約戦略: [使用した戦略名]
```

## 6. 品質基準

要約の品質は以下の優先順位で評価する。

```
1. 事実の正確性（最重要）
   - 数値・データの転記ミスがないか
   - 因果関係の誤認がないか
   - 著者の主張を歪曲していないか

2. カバレッジ（網羅性）
   - 主要な論点が漏れていないか
   - 重要なデータ・結論が含まれているか

3. 読みやすさ
   - 要約単体で内容が理解できるか
   - 論理的な構成になっているか
   - 対象読者に適した表現か
```

## 7. 品質チェックリスト

要約完了前に以下を確認する。

- [ ] 原文の主要な結論・主張が全て含まれているか
- [ ] 数値・データが原文と一致しているか
- [ ] 原文にない情報を付加していないか（ハルシネーション防止）
- [ ] エグゼクティブサマリーだけで要旨が把握できるか
- [ ] 指定された分量・形式の制約を満たしているか
- [ ] 「事実」と「著者の意見・解釈」が区別されているか
- [ ] 専門用語に適切な説明が付されているか
